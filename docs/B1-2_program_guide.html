CODYSSEY B1-2 · PROGRAM GUIDE

React 포트폴리오, 코드로 이해하기

B1-1의 정적인 소개 사이트를 React 기반의 웹 서비스로 바꾼 프로그램입니다. 방문자는 프로젝트를 보고, 관리자는 로그인해 프로젝트를 등록·수정·삭제합니다. 이 설명서는 실제 최신 코드를 기준으로, 화면에서 일어나는 일과 그 뒤의 코드를 나란히 보여줍니다.

코드 조각은 모두 실제 파일에서 그대로 가져왔습니다. 각 코드 상자 위에 파일 경로가 적혀 있습니다. 설명서를 만든 시점(브랜치 claude/epic-clarke-mmra67)의 코드와 같으며, 코드가 바뀌면 설명서도 다시 만들어야 합니다.

학습 순서 (추천)

  1. 큰 그림 — 1. 구조도와 2. React와 JS의 차이를 먼저 봅니다. "어떤 층이 있고, 무엇이 무엇을 부르는지"만 잡으면 됩니다.
  2. 화면 지도 — 3. 폴더와 4. 페이지로 "어느 주소에서 어떤 파일이 일하는지" 연결합니다.
  3. React 핵심 개념 — 5. props → 6. state·useEffect·Context·훅 순서로 읽습니다.
  4. 흐름 따라가기 — 8. 클릭 → 화면, 9. CRUD 흐름을 실제 앱을 켜 놓고 따라 눌러 봅니다.
  5. 데이터와 보안 — 10. Supabase, 11. 인증과 RLS, 12. 테마·언어.
  6. 확인 — 13. 요구사항 연결, 14. 테스트, 15. 구현 상태. 함수가 궁금할 때마다 7. 함수 사전을 찾아봅니다.

02 · REACT VS HTML·CSS·JS

가장 중요한 effect — 데이터 요청 src/hooks/useAsyncData.js

컴포넌트 함수 본문에서 바로 요청하면 "요청 → state 변경 → 다시 그림 → 또 요청"이 무한 반복됩니다. 그래서 요청은 useEffect 안에서 합니다. isLoading은 따로 state로 두지 않고 "지금 요청한 대상(loadData·reloadCount)의 결과가 아직 없다"에서 계산합니다.

11 · AUTH & RLS

관리자 인증과 RLS 권한 보호

보호는 두 겹입니다. 화면(React)은 관리 버튼을 숨기고 관리자 전용 주소를 막는 편의 기능이고, 진짜 보안은 데이터베이스의 RLS(Row Level Security)입니다. 누군가 개발자 도구로 API를 직접 불러도 DB가 거절합니다.

① 화면 쪽 (React)

  • AuthProvider: 세션 확인 → 로그인했으면 checkIsAdmin으로 DB에 관리자인지 물어봄 → isAdmin
  • 관리자일 때만 New·등록·수정·삭제 버튼 표시
  • ProtectedRoute가 /projects/new, /projects/:id/edit를 보호
  • 관리자 확인이 실패하면 "관리자 아님"으로 처리 (안전한 쪽으로 실패)

② DB 쪽 (Supabase RLS)

  • supabase/02_policies.sql
  • 조회: 누구나
  • 등록·수정·삭제: is_admin()이 true일 때만
  • 관리자 = admin_users 표에 등록된 계정 (앱에서 스스로 등록할 방법 없음)
  • 방문자(anon)는 테이블 쓰기 권한 자체가 없음

ProtectedRoute의 판단 순서

확인 중(isLoading)? → "로그인 상태를 확인하는 중입니다."
로그인 안 함(!user)? → /login으로 (원래 주소 기억)
관리자 아님(!isAdmin)? → "관리자 권한이 없는 계정입니다."
관리자 → 안쪽 화면(<Outlet />)
